# API Reference

All request bodies use JSON. Successful responses use `{ "success": true, "data": ... }`; errors use `{ "success": false, "message": "..." }`. Monetary `NUMERIC` values are returned as decimal strings.

## Health

### `GET /health`

Returns `200` with `{ "success": true, "message": "API and database are running" }` when the configured Supabase PostgreSQL database is reachable; otherwise returns `503`.

## Accounts

### `POST /api/accounts`

Create an account. IDs are UUIDs generated by the API; the database supplies the timestamp and initial balance.

Request:

```json
{
  "name": "Operating account"
}
```

Returns `201`:

```json
{
  "success": true,
  "data": {
    "id": "generated-uuid",
    "name": "Operating account",
    "balance": "0.00",
    "createdAt": "2026-10-27T10:00:00.000Z"
  }
}
```

An absent, non-string, or blank name returns `400`.

### `GET /api/accounts/:accountId/balance`

Returns `200`:

```json
{
  "success": true,
  "data": {
    "accountId": "generated-uuid",
    "balance": "0.00"
  }
}
```

An unknown account returns `404`; an empty ID returns `400`.

## Credits and debits

### `POST /api/accounts/:accountId/transactions`

Request:

```json
{
  "type": "credit",
  "amount": "125.50",
  "reference_id": "invoice-2026-001",
  "description": "Invoice payment"
}
```

`type` must be `credit` or `debit`. `amount` must be greater than zero and use ordinary decimal notation; `reference_id` must be a non-empty string unique within the account. `description` is optional.

Returns `201` with the created immutable transaction and `balanceAfter`. A duplicate reference returns `409`, insufficient debit funds return `422`, an unknown account returns `404`, and invalid input returns `400`.

Balance changes and transaction insertion commit or roll back together. The account row is locked while applying a transaction, preventing concurrent withdrawals from overspending.

## Transaction history

### `GET /api/accounts/:accountId/transactions`

Optional query parameters:

| Parameter | Values | Default |
|---|---|---|
| `type` | `credit` or `debit` | No filter |
| `page` | Positive integer | `1` |
| `limit` | Integer from `1` to `100` | `20` |

Example:

```text
GET /api/accounts/{accountId}/transactions?type=debit&page=1&limit=20
```

Returns `200` with `transactions`, `page`, `limit`, `total`, and `totalPages`. Transactions are ordered by `created_at DESC, id DESC`. Invalid filters or pagination return `400`; an unknown account returns `404`.

## Transfers

### `POST /api/transfers`

Request:

```json
{
  "source_account_id": "source-uuid",
  "destination_account_id": "destination-uuid",
  "amount": "25.00",
  "reference_id": "transfer-2026-001",
  "description": "Move funds"
}
```

The source and destination must differ. The operation writes a debit for the source and a credit for the destination in one PostgreSQL transaction, with both accounts locked in stable order. Both entries use the supplied reference ID, unique independently per account.

Returns `201` with source and destination transaction IDs and resulting balances. Invalid input or a same-account transfer returns `400`; an unknown account returns `404`; duplicate references return `409`; insufficient source funds return `422`. A failure leaves both balances and the ledger unchanged.

This endpoint accepts `POST` requests only. A `GET` request (such as opening the URL directly in a browser) returns `405 Method Not Allowed` with `Allow: POST`.

## Status code summary

| Status | Meaning |
|---|---|
| `201` | Account, transaction, or transfer created |
| `200` | Read succeeded |
| `400` | Invalid body, identifier, filter, or pagination |
| `404` | Account not found |
| `409` | Duplicate reference within an account |
| `422` | Insufficient balance |
| `500` | Unexpected server or database error |
| `503` | Health check cannot reach the Supabase PostgreSQL database |
