# Transaction Ledger API Reference

This document describes the HTTP interface provided by the Transaction Ledger backend.

## Base URL

The API is served by the backend on the port configured by `PORT` (default: `3000`). All endpoints use the `/api` prefix except the health check.

## Conventions

- Requests with a body must use `Content-Type: application/json`.
- Successful resource responses use `{ "success": true, "data": ... }`. The health check is a successful message response without a `data` property.
- Errors use `{ "success": false, "message": "..." }`.
- Monetary values backed by PostgreSQL `NUMERIC` are serialized as decimal strings to preserve precision.
- Timestamps are ISO 8601 strings generated by PostgreSQL and serialized in UTC.
- All state-changing `/api` requests require the `X-Ledger-Request: 1` header. The web client sends it automatically; cross-origin clients must use an allowed `FRONTEND_ORIGIN` and credentials.
- Ledger and admin routes require an HTTP-only JWT session cookie. Login endpoints set the cookie; use `/api/auth/logout` to clear it.

## Authentication

### `POST /api/auth/staff/login`

Signs in a staff member using all three credentials.

```json
{ "staff_id": "bhank1_001", "email": "staff@example.com", "password": "staff-password" }
```

### `POST /api/auth/staff/register`

Creates a staff account with an email-bound, single-use invitation key issued by an administrator.

```json
{
  "staff_id": "bhank1_001",
  "name": "Staff Member",
  "email": "staff@example.com",
  "password": "staff-password",
  "invitation_key": "one-time-key"
}
```

The password must be 12–72 UTF-8 bytes. The key is consumed atomically with account creation and must match the invited email. Invalid, used, revoked, or mismatched keys return `401`; duplicate staff IDs or emails return `409`. Registration does not sign the staff member in; they can use the regular staff login afterward.

### `POST /api/auth/admin/login`

Signs in using the `ADMIN_EMAIL` and `ADMIN_PASSWORD_HASH` backend environment settings.

```json
{ "email": "Admin@gmail.com", "password": "Admin@123" }
```

Successful login returns the authenticated user and sets an eight-hour HTTP-only JWT cookie. Invalid credentials return `401`; missing fields return `400`. Login attempts are rate limited.

### `GET /api/auth/me` and `POST /api/auth/logout`

The current-user endpoint returns the signed-in user. Logout clears the cookie. Both require an authenticated session.

### `GET /api/admin/staff` and `POST /api/admin/staff`

Both endpoints require the `admin` role. Staff creation requires `staff_id`, `name`, `email`, and a password of 12–72 UTF-8 bytes. Staff IDs are unique; email uniqueness is case-insensitive. Passwords are bcrypt-hashed before insertion. Duplicate IDs or emails return `409 Conflict`. Staff list responses never include password hashes.

### `PUT /api/admin/staff/:staffId` and `DELETE /api/admin/staff/:staffId`

Both endpoints require the `admin` role. `id` in the URL is the staff record UUID (`sub` from the staff list). Updating requires `staff_id`, `name`, and `email`; an optional password replaces the existing password and must be 12–72 UTF-8 bytes. Staff IDs and emails remain unique, with duplicates returning `409 Conflict`. Delete permanently removes the staff account and invalidates its active sessions. Invalid record IDs return `400`; missing accounts return `404`. Password hashes are never returned.

### `GET /api/admin/invitations`, `POST /api/admin/invitations`, and `DELETE /api/admin/invitations/:id`

All invitation endpoints require the `admin` role. Creating an invitation requires a valid `email`. It returns a randomly generated, single-use key once; the database stores only its SHA-256 hash. Keys are bound to their email, can be revoked while unused, and cannot be retrieved again after creation. Only invitation status and email are returned by the list endpoint.

## Health

### `GET /health`

Checks connectivity to the configured Supabase PostgreSQL database.

**Success — `200 OK`**

```json
{
  "success": true,
  "message": "API and database are running"
}
```

**Database unavailable — `503 Service Unavailable`**

```json
{
  "success": false,
  "message": "Database connection unavailable"
}
```

## Accounts

### `POST /api/accounts`

Creates an account. The API generates the ID, and the database supplies the initial zero balance and creation timestamp.

**Request**

```json
{
  "name": "Operating account"
}
```

`name` must be a non-empty string. Leading and trailing whitespace is removed.

**Success — `201 Created`**

```json
{
  "success": true,
  "data": {
    "id": "generated-uuid",
    "name": "Operating account",
    "balance": "0",
    "createdAt": "2026-10-27T10:00:00.000Z"
  }
}
```

**Possible errors:** `400 Bad Request` for a missing, blank, or non-string name; `500 Internal Server Error` if account creation fails.

### `PUT /api/accounts/:accountId`

Updates an account's name. Leading and trailing whitespace is removed.

**Request**

```json
{
  "name": "Primary operating account"
}
```

**Success — `200 OK`** returns the updated account using the same response shape as account creation.

**Possible errors:** `400 Bad Request` for an invalid account ID or missing, blank, or non-string name; `404 Not Found` if the account does not exist; `500 Internal Server Error` if the update fails.

### `DELETE /api/accounts/:accountId`

Permanently deletes an account only when it has no transactions. Transaction history is retained and accounts referenced by transactions cannot be deleted.

**Success — `200 OK`**

```json
{
  "success": true,
  "data": { "id": "account-id" }
}
```

**Possible errors:** `400 Bad Request` for a blank account ID; `404 Not Found` if the account does not exist; `409 Conflict` if the account has transaction history; `500 Internal Server Error` if deletion fails.

### `GET /api/accounts/:accountId/balance`

Returns the current balance and lifetime credit/debit totals for an account.

**Success — `200 OK`**

```json
{
  "success": true,
  "data": {
    "accountId": "generated-uuid",
    "balance": "125.50",
    "creditTotal": "150.00",
    "debitTotal": "24.50"
  }
}
```

**Possible errors:** `400 Bad Request` for a blank account ID; `404 Not Found` if the account does not exist; `500 Internal Server Error` if retrieval fails.

## Transactions

### `POST /api/accounts/:accountId/transactions`

Creates an immutable credit or debit and updates the account balance in the same database transaction.

**Request**

```json
{
  "type": "credit",
  "amount": "125.50",
  "reference_id": "invoice-2026-001",
  "description": "Invoice payment"
}
```

| Field | Required | Rules |
|---|---|---|
| `type` | Yes | Must be `credit` or `debit`. |
| `amount` | Yes | Positive decimal string or finite JSON number. Must use ordinary decimal notation; signs and exponent notation are not accepted. |
| `reference_id` | Yes | Non-empty string, unique within this account. Whitespace is trimmed. |
| `description` | No | String; defaults to an empty string. Whitespace is trimmed. |

**Success — `201 Created`**

```json
{
  "success": true,
  "data": {
    "id": "generated-transaction-uuid",
    "accountId": "generated-account-uuid",
    "type": "credit",
    "amount": "125.50",
    "description": "Invoice payment",
    "referenceId": "invoice-2026-001",
    "createdAt": "2026-10-27T10:00:00.000Z",
    "balanceAfter": "125.50"
  }
}
```

**Possible errors:** `400 Bad Request` for invalid input; `404 Not Found` if the account does not exist; `409 Conflict` if the reference already exists for the account; `422 Unprocessable Content` if a debit exceeds the available balance; `500 Internal Server Error` for an unexpected failure.

The account row is locked during the balance update. The balance change and transaction insert either both commit or both roll back.

### `GET /api/accounts/:accountId/transactions`

Returns transaction history for one account, ordered newest first by `created_at`, then by `id`.

**Query parameters**

| Parameter | Type | Default | Rules |
|---|---|---|---|
| `type` | String | No filter | If supplied, must be `credit` or `debit`. |
| `page` | Positive integer | `1` | Must be a positive safe integer. |
| `limit` | Integer | `20` | Must be between `1` and `100`. |

**Example**

```text
GET /api/accounts/{accountId}/transactions?type=debit&page=1&limit=20
```

**Success — `200 OK`**

```json
{
  "success": true,
  "data": {
    "transactions": [
      {
        "id": "generated-transaction-uuid",
        "accountId": "generated-account-uuid",
        "type": "debit",
        "amount": "25.00",
        "description": "Office supplies",
        "referenceId": "purchase-2026-001",
        "createdAt": "2026-10-27T10:00:00.000Z"
      }
    ],
    "page": 1,
    "limit": 20,
    "total": 1,
    "totalPages": 1
  }
}
```

History items do not include `balanceAfter`.

**Possible errors:** `400 Bad Request` for invalid account ID, filter, page, or limit; `404 Not Found` if the account does not exist; `500 Internal Server Error` for an unexpected failure.

## Transfers

### `POST /api/transfers`

Transfers funds from one account to another. The API records a debit and a credit within one PostgreSQL transaction.

**Request**

```json
{
  "source_account_id": "source-account-uuid",
  "destination_account_id": "destination-account-uuid",
  "amount": "25.00",
  "reference_id": "transfer-2026-001",
  "description": "Move funds"
}
```

| Field | Required | Rules |
|---|---|---|
| `source_account_id` | Yes | Non-empty string. Must differ from the destination account ID. |
| `destination_account_id` | Yes | Non-empty string. Must differ from the source account ID. |
| `amount` | Yes | Positive decimal string or finite JSON number using ordinary decimal notation. |
| `reference_id` | Yes | Non-empty string that must not already exist on either participating account. |
| `description` | No | String; defaults to an empty string. |

**Success — `201 Created`**

```json
{
  "success": true,
  "data": {
    "referenceId": "transfer-2026-001",
    "amount": "25.00",
    "source": {
      "accountId": "source-account-uuid",
      "transactionId": "generated-debit-uuid",
      "balanceAfter": "75.00"
    },
    "destination": {
      "accountId": "destination-account-uuid",
      "transactionId": "generated-credit-uuid",
      "balanceAfter": "125.00"
    }
  }
}
```

The API locks both accounts in stable ID order to avoid conflicting lock order. Both ledger entries and balance updates commit together or roll back together. The reference ID must not already exist on either account.

**Possible errors:** `400 Bad Request` for invalid input or identical source and destination; `404 Not Found` if either account does not exist; `409 Conflict` if the reference already exists on either account; `422 Unprocessable Content` if the source balance is insufficient; `500 Internal Server Error` for an unexpected failure.

Only `POST` is supported at `/api/transfers`. Other methods return `405 Method Not Allowed` and include `Allow: POST`.

## Error response format

```json
{
  "success": false,
  "message": "A descriptive error message"
}
```

## Status code summary

| Status | Meaning |
|---|---|
| `200` | Read or health check succeeded |
| `201` | Account, transaction, or transfer created |
| `400` | Request body, identifier, filter, or pagination is invalid |
| `404` | Requested account does not exist |
| `405` | HTTP method is not supported for the route |
| `409` | Duplicate transaction reference or account deletion blocked by transaction history |
| `422` | Requested debit or transfer exceeds the available balance |
| `500` | Unexpected server or database error |
| `503` | Health check cannot reach the Supabase PostgreSQL database |
